## 建議實作順序

1. 交付等待分流。
2. 每輪精簡契約與批次錯誤回饋。
3. Progress 與獨立 action 准入隔離。
4. 安全正規化與 condition ID 推導。
5. 寫入分流與跨類型補救路由回歸。

每項先檢查現有實作，再做 UT、真 Runtime loop、既有 Edge／ChatGPT 網頁 IT。網頁 IT 應使用隔離測試目標，不中斷使用者工作；需要額外授權或 URL 時先詢問。

## 共通驗收與紀錄

- 分開記錄：Transport 送出／回讀、Action 准入／執行／驗證、Task 終態。不能混成一個成功或失敗。
- 每次測試記錄 request ID、round、action ID、原始診斷、實際執行結果、驗證證據及最終回覆狀態。
- 比較回覆拒絕率、補救往返數、相同阻塞重複次數；同時檢查安全拒絕未退化，不能只為降低拒絕率放寬契約。
- QUEUED、RUNNING、PARTIAL、UNKNOWN 或尚未測試不得標 PASS／已交付。
- 確認合法操作不因非關鍵格式錯誤被連帶阻塞；失敗 action 仍阻擋依賴它的操作。
- 測試失敗時補記 RCA、最終修法與重測證據；目前本表各項均為待驗證，沒有新增 PASS 宣稱。
