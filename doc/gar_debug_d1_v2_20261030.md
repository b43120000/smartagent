# GAR L4 D1 v2 Live Debug and Evidence Handoff

Base: `c7818582f585173825ef26a80c4df8a437308314` on the existing GAR L4 fix branch. This work is a **D1 v2 protocol-failure E2E debug flow**, not the separate six-step D2 semantic-stagnation scenario. No main merge, publisher, or Update.bat changes.

## One-click workflow

1. Finish/stop the existing WebCopilot Controller (not the browser or Chrome3 profile). Start only one Controller by double-clicking `GAR_debug_webcopiolt.bat`.
2. It uses the saved WebGPT1 URL and the preconfigured existing WebGPT2 conversation. It sets GAR supervisor ON and single-use D1 ON. It opens/reuses both pages via the existing `launch_webcopilot.bat`.
3. Once Controller READY appears, type **exactly** `Explain RAII in C++.` in WebGPT1 without attachments.
4. Observe the result or safe pause. Double-click `collectData.bat` while the current Controller and browser are still available (it also works after they close).
5. The collector prints a full local **folder path** and adjacent **ZIP path** under `localdata/gar_debug_collections/GAR_L4_<timestamp>`. Upload the ZIP or compress the folder. Read `README.txt` and review `webgpt2_review_redacted.json` before sharing.

Run `run_gar_debug_regression.bat` first for the five offline checks (including bounded Composer chunk readback) and strict 204-file Manifest gate. The pre-existing `run_gar_regression.bat` and `run_gar_d1_regression.bat` remain independently runnable and unchanged.

## D1 v2 release safety

Only the first exact eligible request is injected; seven V9-format rejections occur on **original WebGPT1 only**. WebGPT2 uses a distinct browser tab as a read-only supervisory advisor. When Runtime accepts its strict JSON advice and emits `gar_l4_webgpt1_resumed` with original-planner ownership and `supervisor_review_returned=true`, the D1 injector emits `gar_d1_test_resume_release` and stops injecting. The next WebGPT1 Planner call is real, with normal V9 Progress/Terminal gates. A malformed review, changed identity, or unverified/early return does **not** release D1.

## Same-request Live acceptance

Evidence order for one request ID (D1 events without IDs must share the same Controller PID and window):

```text
gar_d1_test_armed
gar_local_repair_handoff
gar_recovery_decision (level=L4)
gar_l4_webgpt1_paused_for_review
gar_l4_webgpt2_advice_received
gar_l4_webgpt1_resumed (planner_owner=ORIGINAL_WEBGPT1)
gar_d1_test_resume_release
protocol_loop_completed (task_outcome=SUCCESS)
```

Offline PASS and opening the two browser pages do not prove Live E2E. An ordinary RAII SUCCESS without these events is **not** a GAR L4 PASS.

## Data collection and privacy

`collectData.bat` reads existing local JSONL, latest regression summary files, Git status/SHA and Manifest attestation. It writes selected request events, a redacted review summary, a preliminary PASS/NOT-PROVEN event report, and an uploadable ZIP. It does **not** include raw browser responses, cookies, user token values, unrelated entire conversation logs or profile files. Some redacted advice wording may still reveal the subject of the task; inspect before uploading.

For a different request: `collectData.bat --request-id WA-...`

The **D2 six-step accepted-progress / Step-3 semantic-stagnation** Live harness requires a separate guarded implementation and acceptance run. Do not claim D2 coverage from this D1 v2 exercise.

## Composer first-chunk readback follow-up (2026-10-31)

The 2fd09b2 Live run accepted WebGPT2 advice and restored WebGPT1, but WebGPT1 Round 8 then failed on the first 4096-char chunk of an 11719-char recovery prompt. The original 2-second readback deadline is now a finite 8-second **read-only** verification window per chunk; there is never a second keyboard write, a forced match, or a retry of an unknown submit. The existing quarantine/UNOWNED_DRAFT protections remain.

A failed chunk leaves content-free `readback_failure` metadata in the original Composer Journal: chunk bounds, attempts, expected/observed lengths and SHA-256 hashes, and the read-only error class. The unchanged `collectData.bat` now uses its updated Python collector to add `composer_journals_redacted.json` and transport error codes to the ZIP. No raw journal, prompt, browser URL or cookies are exported.

**Important for the next Live attempt:** A previous QUARANTINED/UNOWNED_DRAFT state in an older WebGPT1 conversation can block new requests. Preserve the old state and evidence; prefer choosing a **clean WebGPT1 conversation with an empty composer** via `GAR_debug_webcopiolt.bat --webgpt-url "<new existing WebGPT1 conversation URL>"`. Keep the configured WebGPT2 conversation distinct and reuse the existing Chrome3 profile. Never delete a journal, clear an unknown draft automatically, or automatically resubmit the interrupted Round 8.
